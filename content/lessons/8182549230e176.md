## 十、分布式系统与中间件（3-5题）

### 10.1 CAP 与 BASE（必考）

**CAP**：一致性 + 可用性 + 分区容忍 → 三选二
- 网络分区不可避免，所以 P 必选 → 实际是 CP / AP 二选一
- **CP**（牺牲可用性保一致）：HBase、ZooKeeper、etcd、Consul（强一致模式）
- **AP**（牺牲一致性保可用）：Eureka、Cassandra、CouchDB、DNS、**Redis（默认主从异步复制）**

> 注：**Redis 主从复制默认是异步**，主节点宕机时可能丢数据，属于 AP；只有在 WAIT 命令或同步复制配置下才偏 CP。常见误区是把 Redis Sentinel 当成 CP，实际上 Sentinel 只是故障转移机制，不改变 Redis 的 AP 本质。

**BASE**：基本可用、软状态、最终一致（互联网架构主流）

### 10.2 分布式一致性

**Paxos / Raft**：基于多数派的强一致协议
**Gossip**：最终一致，去中心化
**Quorum (NWR)**：N 副本数、W 写副本数、R 读副本数；W+R>N 强一致

### 10.3 负载均衡算法

- 轮询、加权轮询
- 随机、加权随机
- 最小连接数、最小响应时间
- 一致性哈希（节点变化时影响小）
- IP 哈希（同一用户落同一节点，会话粘滞）

### 10.4 缓存策略

- **Cache Aside**（旁路）：先读缓存，未命中读数据库；写时先更新数据库再删缓存
- **Read/Write Through**：缓存与 DB 同步
- **Write Behind**：异步写回 DB（性能高但有丢数据风险）

**缓存问题**：
- 击穿：单 key 失效 → 互斥锁
- 穿透：查不存在 key → 布隆过滤器
- 雪崩：大量 key 同时失效 → 错峰过期

### 10.5 消息队列

**作用**：解耦、异步、削峰

**主流对比**：
| MQ | 特点 |
|----|------|
| Kafka | 高吞吐、日志型、分区有序 |
| RabbitMQ | AMQP、企业、可靠 |
| RocketMQ | 阿里、事务消息 |
| ActiveMQ | 老牌、JMS |

### 10.6 容器与云原生

| 概念 | 要点 |
|------|------|
| Docker | 容器化技术、共享内核 |
| K8s | 容器编排：Pod、Service、Deployment、Ingress |
| 服务网格 | Istio、Linkerd（Sidecar） |
| Serverless | 无服务器、FaaS、按量付费 |
| 微服务治理 | 注册发现(Eureka/Nacos)、配置(Apollo)、网关(Zuul/Gateway)、熔断(Hystrix/Sentinel)、链路(Zipkin/SkyWalking) |

**云服务模型**：
- IaaS：基础设施（AWS EC2、阿里云 ECS）
- PaaS：平台（Heroku、阿里云 ACK）
- SaaS：软件（钉钉、Office 365）

**部署模型**：公有云、私有云、混合云、社区云
