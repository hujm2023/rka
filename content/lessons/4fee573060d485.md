## 四、各题型答题框架

### 1. 架构设计题

**常见问题模式**：给出场景，分析架构风格/模式的适用性

**答题框架**：
```
1. 明确指出推荐的架构风格/模式名称
2. 简述该架构的核心特点（2-3 点）
3. 结合题目场景说明为什么适合（匹配需求）
4. 指出可能的风险和应对措施
5. 画架构图（如有要求）
```

**示例答题**：
> 推荐采用微服务架构。
> 理由：(1) 系统需要独立部署各业务模块 → 微服务支持独立部署和扩展；
> (2) 团队规模大，需并行开发 → 微服务天然支持团队自治；
> (3) 系统对可用性要求高 → 服务隔离，单个服务故障不影响整体。

### 2. 设计模式题

**常见问题模式**：根据类图/代码填空，分析使用了什么设计模式

**答题框架**：
```
1. 识别设计模式名称
2. 说明该模式的意图和结构
3. 结合题目代码/类图指出各角色对应关系
4. 补全代码/类图中的空白部分
5. 说明使用该模式的优点
```

**关键**：熟记 23 种 GoF 设计模式的类图和角色名称

### 3. 数据库设计题

**常见问题模式**：根据需求画 ER 图、做规范化分析

**答题框架**：
```
1. 识别实体和属性
2. 确定实体间关系（1:1, 1:N, M:N）
3. 画 ER 图（标注基数）
4. 进行规范化分析（指出函数依赖，判断范式等级）
5. 如需分解，给出分解后的关系模式
```

### 4. 质量属性/架构评估题

**答题框架**：
```
1. 识别题目涉及的质量属性（性能、可用性、安全性等）
2. 分析质量属性场景六要素：
   - 刺激源 → 刺激 → 环境 → 制品 → 响应 → 响应度量
3. 给出对应的架构策略
4. 分析策略间的权衡关系
```

### 5. 项目管理案例题（项管师）

**答题框架**：
```
1. 指出案例中存在的问题（逐条列举）
2. 分析产生问题的原因
3. 给出改进建议/正确做法
4. 引用相关理论或过程组支撑
```
