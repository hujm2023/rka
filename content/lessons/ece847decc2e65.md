### 3.2 必备知识点

#### ① 集群与负载均衡

**集群类型**：
- 高可用集群（HA）：主备/双活，故障切换
- 负载均衡集群（LB）：分摊请求
- 高性能集群（HPC）：并行计算

**负载均衡算法**：
| 算法 | 特点 | 适用 |
|------|------|------|
| 轮询 RR | 顺序分配 | 节点性能相近 |
| 加权轮询 WRR | 按权重 | 节点性能不同 |
| 随机 | 概率分配 | 简单负载 |
| 最小连接数 | 选连接数少的 | 长连接业务 |
| 最小响应时间 | 选最快的 | 性能敏感 |
| 一致性哈希 | 节点变化影响小 | 缓存集群 |
| IP Hash | 同 IP 落同节点 | 会话保持 |

**LVS 三种模式**：
- NAT：通过修改请求目的地址
- DR（直接路由）：性能最好（最常用）
- TUN（IP 隧道）：跨网段

#### ② 缓存

**多级缓存**：浏览器 → CDN → Nginx → 应用层 → 分布式缓存(Redis) → DB

**缓存模式**：
- **Cache Aside**（旁路缓存，最常用）：
  - 读：先缓存，未命中读 DB 并写缓存
  - 写：先更新 DB，再删除缓存
- **Read/Write Through**：缓存与 DB 同步
- **Write Behind**：异步写回 DB（高性能但有数据丢失风险）

**三大缓存问题**（必考）：
| 问题 | 原因 | 解决 |
|------|------|------|
| **缓存击穿** | 单个热点 key 过期，大量请求打到 DB | 互斥锁、永不过期、热点预热 |
| **缓存穿透** | 查询不存在的数据，缓存层无效 | 布隆过滤器、空值缓存 |
| **缓存雪崩** | 大量 key 同时失效 | 错峰过期（随机TTL）、多级缓存 |

**Redis 数据类型**：String、List、Hash、Set、Sorted Set、Bitmap、HyperLogLog、Stream

**Redis 持久化**：
- RDB（快照）：定时快照，恢复快但可能丢数据
- AOF（日志）：每次操作追加，丢失少但文件大
- 混合持久化（Redis 4.0+）

**Redis 集群方案**：
- 主从复制 + 哨兵
- Cluster 集群（哈希槽 16384）
- Codis（豌豆荚开源）

#### ③ 消息队列

**作用**（必背三要素）：
1. **解耦**：生产者消费者独立
2. **异步**：提高响应速度
3. **削峰**：应对突发流量

**主流 MQ 对比**：
| MQ | 吞吐 | 延迟 | 特性 | 适用 |
|----|------|------|------|------|
| Kafka | 极高(百万级) | ms-s | 日志型、分区有序 | 大数据、日志 |
| RocketMQ | 高(十万级) | ms | 事务消息、阿里 | 金融、电商 |
| RabbitMQ | 中(万级) | μs | AMQP、灵活路由 | 企业、可靠传输 |
| ActiveMQ | 较低 | ms | JMS、老牌 | 传统企业 |

**消息可靠性**：
- 不丢失：持久化 + ACK + 重试
- 不重复：幂等性、去重表、Token 机制
- 顺序消息：单分区、Hash 分区

#### ④ 微服务架构

**核心特征**：
1. 服务独立部署
2. 去中心化治理
3. 围绕业务能力组织
4. 智能端点和哑管道
5. 失败设计（Design for Failure）
6. 演进式设计

**SOA vs 微服务对比**（必考辨析）：
| 维度 | SOA | 微服务 |
|------|-----|--------|
| 通信 | ESB（智能管道） | HTTP/RPC（哑管道） |
| 数据 | 共享数据库 | 每服务独立数据库 |
| 粒度 | 粗 | 细 |
| 部署 | 集中部署 | 独立部署 |
| 治理 | 集中 | 去中心化 |
| 复用度 | 高 | 低（接受冗余） |
| 难度 | 中 | 高（运维复杂） |

**微服务治理组件**：
| 类别 | 主流方案 |
|------|---------|
| 注册发现 | Eureka、Nacos、Consul、ZooKeeper |
| 配置中心 | Apollo、Nacos、Spring Cloud Config |
| 网关 | Spring Cloud Gateway、Zuul、Kong、APISIX |
| 熔断限流 | Hystrix、Sentinel、Resilience4j |
| 调用追踪 | Zipkin、SkyWalking、Jaeger |
| 服务网格 | Istio、Linkerd、Consul Connect |

**服务拆分原则**：
- 单一职责
- 业务边界（DDD 限界上下文）
- 高内聚低耦合
- 团队规模匹配（two-pizza team）

#### ⑤ Web 安全

**OWASP Top 10（2021 标准版，高频）**：

| 编号 | 项目 | 典型防御 |
|------|------|---------|
| A01 | **失效的访问控制** Broken Access Control | RBAC、最小权限、强制服务端校验 |
| A02 | **加密机制失效** Cryptographic Failures | TLS 1.3、强密钥管理、敏感数据不明文存储 |
| A03 | **注入** Injection（SQL/XSS/命令注入） | 参数化查询、输入校验、输出转义 |
| A04 | **不安全设计** Insecure Design | 威胁建模、安全设计模式、安全开发生命周期 |
| A05 | **安全配置错误** Security Misconfiguration | 硬化基线、最小化默认配置、定期审计 |
| A06 | **易受攻击和过时的组件** Vulnerable and Outdated Components | SCA 扫描、依赖更新、白名单管理 |
| A07 | **身份识别和身份验证失败** Identification and Authentication Failures | MFA、强密码策略、防爆破限流 |
| A08 | **软件和数据完整性失败** Software and Data Integrity Failures | 数字签名验证、CI/CD 完整性校验、防反序列化漏洞 |
| A09 | **安全日志和监控失败** Security Logging and Monitoring Failures | 集中日志、SIEM、关键操作审计 |
| A10 | **服务器端请求伪造 SSRF** Server-Side Request Forgery | URL 白名单、网段隔离、禁用危险协议 |

> ⚠️ 常见易错点：CSRF（跨站请求伪造）已**不在 OWASP 2021 Top 10 单列**，被合并到 A01（失效的访问控制）类目下。考试中如题干提到"防 CSRF"，对应 A01 类防御（Token 校验、SameSite Cookie、Referer 校验）。

**关键变化（OWASP 2017 → 2021）**：
- 新增：A04 不安全设计、A08 软件和数据完整性失败、A10 SSRF
- 合并/重组：CSRF / XXE 不再单列；XSS 合入 A03 注入

#### ⑥ 容器与云原生

**Docker**：
- 镜像（image）：只读模板
- 容器（container）：镜像运行实例
- Dockerfile：构建脚本
- Docker Compose：单机多容器编排

**Kubernetes 核心概念**：
| 概念 | 作用 |
|------|------|
| Pod | 最小调度单位（一个或多个容器） |
| Deployment | 无状态服务管理 |
| StatefulSet | 有状态服务（如数据库） |
| DaemonSet | 每节点跑一个 |
| Service | 服务发现与负载均衡 |
| Ingress | 七层路由 |
| ConfigMap | 配置 |
| Secret | 敏感信息 |
| PV/PVC | 持久化存储 |
| Namespace | 资源隔离 |

**云原生 12 要素**（CNCF）：基准代码、依赖、配置、后端服务、构建-发布-运行、进程、端口绑定、并发、易处理、开发/生产环境一致、日志、管理进程

### 3.3 题 2 答题模板

**典型问法 1**：选型对比题（如选 Redis 还是 Memcached）
- 表格对比 → 结论 → 理由

**典型问法 2**：架构改造题（如单体改微服务）
- 现状问题 → 改造方案 → 优势 → 风险 → 应对

**典型问法 3**：性能/安全/可用性方案
- 问题分析 → 战术列举（缓存/CDN/异步/...）→ 选择理由
