### 2.2 必背：6 部分质量属性场景（核心）

每个质量属性场景由 **6 个部分**构成：

| 编号 | 名称 | 含义 | 示例 |
|------|------|------|------|
| 1 | **刺激源** Source | 刺激的发源地 | 用户、内部系统、外部攻击者 |
| 2 | **刺激** Stimulus | 到达系统的事件 | 请求、故障、攻击 |
| 3 | **制品** Artifact | 被刺激的部分 | 系统、数据库、模块 |
| 4 | **环境** Environment | 系统运行状态 | 正常运行、降级、过载 |
| 5 | **响应** Response | 系统采取的动作 | 处理、记录、拒绝 |
| 6 | **响应度量** Measure | 量化指标 | 响应时间≤2秒、可用性≥99.99% |

**必考题型**：给一段描述，要求**填入 6 部分的对应内容**或判断属于哪个质量属性

**示例题（2019 真题改编）**：
> "在系统正常运行情况下，系统在 1 秒钟内处理来自外部用户的 1000 个并发请求"
- 刺激源：外部用户
- 刺激：1000 个并发请求
- 制品：系统
- 环境：正常运行
- 响应：处理请求
- 响应度量：1 秒钟内 / 1000 并发
- → 这是**性能**质量属性场景

### 2.3 6 大质量属性详解

#### ① 可用性 Availability

**关注**：系统正常服务时间比例
**度量**：MTTF / MTBF / MTTR / 可用性百分比（99.9%、99.99%）

**典型战术**（必背）：
- **错误检测**：命令/响应、心跳(Heartbeat)、异常检测
- **错误恢复**：表决、主动冗余（热备）、被动冗余（温备/冷备）、备件、回滚、重试、降级
- **错误预防**：从服务中删除（清除）、事务、进程监视器

**关键词识别**：故障、宕机、恢复、容错、冗余、备份、心跳

#### ② 性能 Performance

**关注**：响应时间、吞吐量
**度量**：延迟、TPS、QPS、并发数

**战术**：
- **资源需求**：减少计算开销、降低事件率、限制执行时间、限制队列大小
- **资源管理**：引入并发、维持多个副本（数据/计算）、增加可用资源
- **资源仲裁**：调度策略（FIFO、固定优先级、动态优先级、SJF）

**关键词**：响应时间、吞吐量、延迟、并发、性能瓶颈、缓存、负载均衡、CDN、异步

#### ③ 安全性 Security

**关注**：抵抗攻击、保护数据
**度量**：检测/抵抗攻击的能力、恢复时间

**战术**：
- **抵抗攻击**：用户认证、用户授权、维护数据机密性/完整性、限制暴露、限制访问
- **检测攻击**：入侵检测系统 IDS
- **从攻击中恢复**：恢复=可用性战术；识别攻击者=审计追踪

**关键词**：认证、授权、加密、防火墙、入侵检测、审计、CA 证书

#### ④ 可修改性 Modifiability

**关注**：变更的成本和难度
**度量**：变更时间、变更成本、变更影响范围

**战术**：
- **局部化变更**：维持高内聚、抽象通用服务、预期期望变更
- **防止连锁反应**：信息隐藏、维持现有接口、限制通信路径、使用中介
- **推迟绑定时间**：运行时注册、配置文件、多态、组件替换、参数化

**关键词**：扩展、修改、新增模块、配置化、解耦、热插拔

#### ⑤ 可测试性 Testability

**战术**：内置监视器、记录/回放、接口实现分离、依赖注入

**关键词**：单元测试、自动化、Mock、覆盖率

#### ⑥ 易用性 Usability

**战术**：分离用户接口（MVC）、支持用户主动（取消、撤销、聚集、再使用）

**关键词**：用户体验、操作便捷、撤销、引导、培训

### 2.4 必背：ATAM 评估（Architecture Tradeoff Analysis Method，架构权衡分析方法）

**ATAM 9 步骤**（每年都可能考）：

```
阶段一：演示
1. 介绍 ATAM 方法
2. 介绍商业目标
3. 介绍待评估架构

阶段二：调查与分析
4. 识别架构方法（架构风格、模式）
5. 生成质量属性效用树
6. 分析架构方法（针对效用树）

阶段三：测试
7. 集体讨论场景并定优先级
8. 再次分析架构方法

阶段四：报告
9. 展示评估结果
```

**3 大核心输出（必考）**：

| 概念 | 定义 | 识别要点 |
|------|------|---------|
| **敏感点** Sensitivity Point | 影响**单个**质量属性的架构决策 | "为提高 X，采用 Y" |
| **权衡点** Tradeoff Point | 影响**多个**质量属性的架构决策 | "同时影响 X 和 Z"，常是矛盾权衡 |
| **风险点** Risk | 可能引起质量目标无法达成的决策 | "可能导致..."、"存在风险" |
| **非风险点** Non-Risk | 经过分析的好的架构决策 | "明确合理"、"已验证" |

**经典识别题套路**（必考！）：
> 题目给若干描述，让你填到敏感点/权衡点/风险点/非风险点

**判别口诀**：
- 描述涉及"提高/影响 1 个属性" → **敏感点**
- 描述涉及"同时影响多个属性，需权衡"→ **权衡点**
- 描述含"可能"、"风险"、"难以确定" → **风险点**
- 描述明确"经过验证"、"合理"、"成熟" → **非风险点**

**典型例题**：
> ① "为提高响应速度，使用 Redis 集群作为缓存层" → **敏感点**（仅影响性能）
> ② "采用主从同步复制，强一致性同时降低了写入性能" → **权衡点**（同时影响一致性和性能）
> ③ "暂时无法估计第三方接口的响应时间稳定性" → **风险点**
> ④ "采用 Nginx 集群进行负载均衡，已在多个项目验证" → **非风险点**

### 2.5 效用树（Utility Tree）

**结构**：根节点(效用) → 质量属性 → 属性细化 → 场景叶子节点
每个叶子标注 **(重要性, 实现难度)**：H/M/L

**示例**：
```
效用 Utility
├── 性能 Performance
│   ├── 数据延迟：在线交易响应≤2s (H, M)
│   └── 事务吞吐：支持 5000 TPS (H, H)
├── 可用性 Availability
│   ├── 硬件故障：故障 5min 内恢复 (H, L)
│   └── 软件容错：服务降级时核心可用 (M, M)
├── 安全性 Security
│   ├── 数据加密：敏感数据 AES 加密 (H, L)
│   └── 访问控制：基于 RBAC 模型 (M, L)
└── 可修改性 Modifiability
    ├── 接口扩展：新增 API≤2 人天 (M, L)
    └── 业务规则：配置化修改 (H, M)
```

**填空题套路**：题目给场景描述，让你画或补全效用树（标 H/M/L）

### 2.6 SAAM 方法（Software Architecture Analysis Method，软件架构分析方法）

| 维度 | SAAM | ATAM |
|------|------|------|
| 提出时间 | 早(1990s) | 晚 |
| 主要关注 | 可修改性、功能性 | 多个质量属性权衡 |
| 评估方式 | 场景驱动 | 场景+效用树 |
| 适用阶段 | 架构早期 | 架构评估全过程 |

**SAAM 步骤**：
1. 形成场景（直接场景 / 间接场景）
2. 描述架构
3. 场景分类与确定优先级
4. 单个场景评估
5. 场景交互评估
6. 形成总体评价

**直接场景**：架构能直接支持
**间接场景**：架构需要修改才能支持（用于评估可修改性）

### 2.7 CBAM（Cost Benefit Analysis Method，成本效益分析方法）

- 在 ATAM 之后做经济性评估
- 关注**ROI（投资回报率）**
- 流程：整理场景 → 确定优先级 → 估算收益 → 估算成本 → 计算 ROI → 决策

### 2.7.1 SAAM / ATAM / CBAM 三兄弟辨析（必考）

> 三种架构评估方法是案例题与选择题高频辨析点，**全称、关注点、使用阶段**都要记牢。

| 缩写 | 全称（英文）| 中文 | 提出时间 | 核心关注 |
|------|-----------|------|---------|---------|
| **SAAM** | **S**oftware **A**rchitecture **A**nalysis **M**ethod | 软件架构**分析**方法 | 1994（最早） | 可修改性、功能性 |
| **ATAM** | **A**rchitecture **T**radeoff **A**nalysis **M**ethod | 架构**权衡分析**方法 | 1998 | 多质量属性权衡 |
| **CBAM** | **C**ost **B**enefit **A**nalysis **M**ethod | **成本效益**分析方法 | ATAM 之后 | ROI 投资回报率 |

**🎯 一句话记忆**：

> **"SAAM 看改、ATAM 看权衡、CBAM 看钱"**

- **SAAM** 早，先关注**改不改得动**（可修改性）
- **ATAM** 晚，关注**多属性的取舍**（权衡）
- **CBAM** 最后，关注**改造值不值这个钱**（ROI）

**使用先后顺序**：SAAM → ATAM → CBAM（早期分析 → 多属性评估 → 经济性决策）

**英文助记**：
- S**A**AM = **A**nalysis（分析）
- AT**A**M = Tradeoff **A**nalysis（权衡分析）
- **C**BAM = **C**ost（成本）—— 看到 C 想到 Cost（钱）
