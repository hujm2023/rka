### 5.2 23 种设计模式速查（必背）

#### 🎯 三大类型总览（先掌握分类再背具体模式）

| 维度 | 创建型（5 个） | 结构型（7 个） | 行为型（11 个） |
|------|---------------|---------------|----------------|
| **关注点** | 怎么 new 对象 | 怎么拼装对象 | 对象怎么协作 |
| **侧重** | 对象**产生** | 对象**组装**（静态结构） | 对象**协作**（动态交互） |
| **关键动词** | new / clone / build | 组合 / 包装 / 转换 | 通知 / 传递 / 切换 |
| **题干关键词** | "创建"、"实例"、"工厂" | "接口"、"组合"、"包装"、"树形" | "算法"、"流程"、"通知"、"状态" |
| **代表模式** | 单例、工厂方法、抽象工厂 | 适配器、装饰、代理、外观 | 观察者、策略、责任链、命令、状态 |

> 💡 **盖房子类比**：
> - **创建型** = 怎么造砖造瓦（生产建材）
> - **结构型** = 怎么砌墙搭框架（建材组装）
> - **行为型** = 水电怎么走线、住户怎么沟通（运行协作）

**🎯 3 步识别法（场景题答题套路）**：

```
Step 1：先判大类（看题干关键词）
   含"创建/实例/工厂/唯一"   → 创建型
   含"接口/包装/兼容/树形/简化" → 结构型
   含"算法/流程/通知/状态/链"   → 行为型

Step 2：再匹配具体模式（见下表关键词列）
   "全局唯一" → 单例   "动态增强功能" → 装饰
   "接口不兼容" → 适配器   "一对多通知" → 观察者
   "多级处理" → 责任链   "状态切换" → 状态
   "封装请求/撤销" → 命令   "算法切换" → 策略

Step 3：套答题话术
   "本场景需要××（关键词），符合××模式的意图。
    该模式的核心思想是××，能够××（解决的问题）。"
```

**🔥 易混淆模式对比（高频考点）**：

| 对比 | 区别 |
|------|------|
| 适配器 vs 代理 | 适配器**改变**接口，代理**保持**接口 |
| 装饰 vs 代理 | 装饰**增强功能**，代理**控制访问** |
| 外观 vs 适配器 | 外观**简化**已有接口，适配器**转换**接口 |
| 策略 vs 状态 | 策略**客户端主动选**算法；状态**对象内部自动**切换 |
| 观察者 vs 中介者 | 观察者**一对多**单向通知；中介者**多对多**集中协调 |
| 责任链 vs 命令 | 责任链**多个处理者依次**判断；命令**封装单个**请求 |
| 模板方法 vs 策略 | 模板方法用**继承**变细节；策略用**组合**换算法 |
| 工厂方法 vs 抽象工厂 | 工厂方法造**一类**产品；抽象工厂造**一族**产品 |

#### 创建型（5 个）

**1. 单例 Singleton**
- 应用：连接池、配置管理、日志
- 实现要点：私有构造、静态实例、获取实例方法
```java
public class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) instance = new Singleton();
        return instance;
    }
}
```

**2. 工厂方法 Factory Method**
- 应用：JDBC、日志框架
- 关键词："**让子类决定**实例化哪个类"
```java
abstract class Creator { abstract Product factoryMethod(); }
class ConcreteCreatorA extends Creator { Product factoryMethod(){return new ProductA();} }
```

**3. 抽象工厂 Abstract Factory**
- 应用：跨平台 UI、主题切换
- 关键词："**产品族**"、"多个相关产品"

**4. 建造者 Builder**
- 应用：StringBuilder、构造复杂对象
- 关键词："**分步构建**"、"Director + Builder"

**5. 原型 Prototype**
- 应用：对象克隆、Java 的 Cloneable
- 关键词："**克隆**"、"复制创建"

#### 结构型（7 个）

**6. 适配器 Adapter**
- 应用：旧接口适配新接口、Stream/Reader 适配
- 关键词："**接口转换**"
- 类适配器（继承）vs 对象适配器（组合，更常用）

**7. 桥接 Bridge**
- 应用：跨平台、形状-颜色独立变化
- 关键词："**抽象与实现分离**"、"两个变化维度"

**8. 组合 Composite**
- 应用：文件系统、组织架构、菜单
- 关键词："**树形结构**"、"部分-整体"
- 一致对待叶子节点和组合节点

**9. 装饰器 Decorator**
- 应用：Java IO 流、日志增强
- 关键词："**动态添加职责**"、"包装"
- 与继承的区别：动态、灵活、不污染原类

**10. 外观 Facade**
- 应用：库的统一入口、SDK
- 关键词："**简化接口**"、"门面"

**11. 享元 Flyweight**
- 应用：字符串常量池、棋子复用、连接池
- 关键词："**共享细粒度**"、"内部状态/外部状态"

**12. 代理 Proxy**
- 应用：远程代理（RPC）、虚代理（懒加载）、保护代理（权限）、动态代理（Spring AOP）
- 关键词："**代理访问**"

#### 行为型（11 个）

**13. 责任链 Chain of Responsibility**
- 应用：审批流、过滤器链（Filter）、Servlet
- 关键词："**链式处理**"、"多个对象处理请求"

**14. 命令 Command**
- 应用：撤销/重做、任务队列、按钮事件
- 关键词："**请求封装为对象**"、"撤销"
- 角色：Invoker、Command、Receiver

**15. 解释器 Interpreter**
- 应用：DSL、规则引擎、SQL 解释
- 关键词："**文法解释**"

**16. 迭代器 Iterator**
- 应用：集合遍历
- 关键词："**遍历不暴露内部**"

**17. 中介者 Mediator**
- 应用：聊天室、MVC 控制器、机场塔台
- 关键词："**通过中介通信**"、"减少多对多耦合"

**18. 备忘录 Memento**
- 应用：撤销操作、游戏存档
- 关键词："**保存恢复状态**"、"快照"
- 角色：Originator、Memento、Caretaker

**19. 观察者 Observer**
- 应用：发布订阅、事件监听、MVC 中 Model→View
- 关键词："**一对多依赖**"、"自动通知"
- 推模型 vs 拉模型

**20. 状态 State**
- 应用：订单状态机、TCP 连接状态、电梯
- 关键词："**对象行为随状态改变**"
- vs 策略：状态会自动切换、强调状态转换

**21. 策略 Strategy**
- 应用：促销算法、支付方式、排序算法
- 关键词："**算法可替换**"、"策略族"
- vs 状态：策略由客户端选择、不会自动切换

**22. 模板方法 Template Method**
- 应用：钩子方法、抽象类基础流程
- 关键词："**算法骨架**"、"子类重写步骤"

**23. 访问者 Visitor**
- 应用：编译器 AST 处理、复杂数据结构操作
- 关键词："**双分派**"、"不修改类增加新操作"
- 角色：Visitor、Element、ObjectStructure

### 5.3 易混设计模式辨析（必考）

| 对比 | 区别 |
|------|------|
| **工厂方法 vs 抽象工厂** | 前者一个产品等级；后者**产品族**（多等级） |
| **适配器 vs 装饰器** | 适配器**改接口**；装饰器**加功能**（接口不变） |
| **适配器 vs 桥接** | 适配器**事后**；桥接**事前**设计 |
| **代理 vs 装饰器** | 代理**控制访问**；装饰器**增强功能** |
| **策略 vs 状态** | 策略**客户端选择**；状态**自动切换** |
| **策略 vs 模板方法** | 策略**组合**（运行时换）；模板**继承**（编译时） |
| **观察者 vs 中介者** | 观察者**一对多直接通知**；中介者**多对多经中介** |
| **命令 vs 策略** | 命令**封装请求**（带历史）；策略**封装算法** |
| **组合 vs 装饰器** | 组合**树形结构**；装饰器**线性嵌套** |
| **外观 vs 中介者** | 外观**单向**简化；中介者**双向**协调 |

### 5.4 UML 类图核心要点

**类图三要素**：
```
+----------------+
|    类名        |
+----------------+
| - 属性: 类型   |  (- 私有, + 公有, # 保护, ~ 包)
+----------------+
| + 方法(): 类型 |
+----------------+
```

**关系符号（必考）**：
| 关系 | 符号 | 实例 |
|------|------|------|
| 依赖 | 虚线箭头 →┄→ | 方法参数、局部变量 |
| 关联 | 实线箭头 →→ | 类成员变量 |
| 聚合 | 空心菱形 ◇— | 部门-员工（员工可属其他） |
| 组合 | 实心菱形 ◆— | 人-心脏（同生死） |
| 泛化 | 空心三角 △— | 子类→父类 |
| 实现 | 虚线空心三角 △┄ | 类→接口 |

**类图填空套路**：
- 给定类和职责描述
- 要求标注：类间关系、关键属性、关键方法、多重性（1, 0..1, *, 1..*）

### 5.5 时序图与状态图

**时序图**（Sequence Diagram）：
- 强调**时间顺序**
- 元素：参与者（生命线）、消息（同步/异步/返回）、激活条
- 题型：补全消息流向

**状态图**（State Diagram）：
- 描述对象**状态变化**
- 元素：初始状态●、状态、转换、终止状态◉
- 题型：补全状态、触发事件、动作

### 5.6 代码填空高频套路

**模式代码识别口诀**：

| 模式 | 关键代码特征 |
|------|-------------|
| 单例 | `getInstance()`, `private static instance` |
| 工厂方法 | `abstract createProduct()`, 子类返回不同 Product |
| 装饰器 | 持有被装饰对象引用，方法中调用并增强 |
| 适配器 | 持有被适配对象，方法名对接新接口 |
| 代理 | 持有真实对象引用，调用前后做拦截 |
| 观察者 | `attach/detach`、`notify()`、`update()` |
| 策略 | Context 持有 Strategy 接口引用 |
| 模板方法 | 抽象类含 `final` 模板 + 多个抽象步骤 |
| 命令 | `execute()` 方法、Invoker 持有 Command |
| 状态 | Context 持有 State 引用，State 内 setState 切换 |
| 责任链 | 持有 nextHandler 引用，递归调用 |

### 5.7 题 4 答题模板

**典型 5 小问结构**：
1. **场景适合的设计模式**：识别 + 名称 + 模式分类（创/结/行）
2. **设计模式的优点 / 适用场景**：3-4 条要点
3. **类图补全**：标关系、多重性、属性、方法
4. **代码填空**：按模式标准代码套路
5. **若需求变化，模式如何应对**：体现模式的扩展性
