### 4.2 必备知识点

#### ① 必背：E-R 图补全（高频）

**E-R 图四要素**：实体（矩形）+ 属性（椭圆）+ 联系（菱形）+ 弱实体（双矩形）

**联系基数**：1:1、1:N、M:N

**🎯 E-R 转关系模式口诀**：

> **"一对一爱合并、一对多向多放、多对多必独立"**

**E-R 转关系模式规则**：
| 联系类型 | 转换规则 | 口诀 |
|---------|---------|------|
| 1:1 | 任一方加另一方主键作为外键，或合并为一张表 | 爱合并 |
| 1:N | **N 端**加 1 端主键作为外键 | 向多放 |
| M:N | **必须独立成新关系**，主键 = 双方主键组合 | 必独立 |
| 多元联系 | 独立成关系，主键 = 各方主键组合 | （同 M:N） |
| 弱实体 | 独立成关系，主键 = 自身部分键 + 强实体主键 | 依附强实体 |

**🎯 候选键求解口诀（4 类划分法）**：

> **"L 必入、N 必入、R 必不入、LR 试探"**

| 类别 | 含义 | 处理 |
|------|------|------|
| **L 类** | 只在函数依赖**左**部出现 | **必属**候选键 |
| **N 类** | 函数依赖中**不出现**的属性 | **必属**候选键 |
| **R 类** | 只在函数依赖**右**部出现 | **必不属**候选键 |
| **LR 类** | **左右都**出现 | 求闭包试探 |

> 💡 求出 L+N 属性集合后，求闭包能推出全部属性 → 该集合即为唯一候选键；否则需把 LR 类属性逐个加入试探。

**填空套路**：题目给场景，要求：
- 补充缺失的实体或联系
- 给出关系模式（含主键、外键）
- 标识候选键

**📌 完整真题演示（学生选课系统）**

> **题干**：某学校开发选课系统：学生(学号、姓名、专业)选修课程(课程号、课程名、学分)，每门课由一位教师(教师号、姓名)讲授，学生选课得到成绩。

**Step 1：识别实体与联系**

- 实体：**学生**、**课程**、**教师**
- 联系：
  - 学生 ── M:N ──{**选修**}── 课程（联系属性：**成绩**）
  - 课程 ── N:1 ──{**讲授**}── 教师

**Step 2：套口诀转关系模式**

- **学生**(<u>学号</u>, 姓名, 专业)
- **教师**(<u>教师号</u>, 姓名)
- **课程**(<u>课程号</u>, 课程名, 学分, 教师号\*) ← 1:N 向多放，N 端加外键
- **选修**(<u>学号\*, 课程号\*</u>, 成绩) ← M:N 必独立，主键 = 双方主键组合

> 约定：主键加下划线、外键标 `*`；外键引用关系：教师号 → 教师(教师号)、学号 → 学生(学号)、课程号 → 课程(课程号)。

**Step 3：候选键标注**

| 关系 | 候选键 | 判定 |
|------|--------|------|
| 学生 | {学号} | 学号 L 类必入 |
| 教师 | {教师号} | 教师号 L 类必入 |
| 课程 | {课程号} | 课程号 L 类必入 |
| 选修 | {学号, 课程号} | 两者 L 类联合 |

**Step 4：范式判定（以"选修"表为例）**

- {学号, 课程号} → 成绩 ✅（联合决定成绩）
- 学号 ⇏ 成绩，课程号 ⇏ 成绩 → **无部分依赖** → 满足 **2NF**
- 无传递依赖 → 满足 **3NF**
- 主属性也无部分/传递依赖 → 满足 **BCNF** ✅

#### ② 必背：SQL 编写

**经典题型**：
1. 创建表（含 PK、FK、约束）
2. 复杂查询（嵌套、关联、聚合）
3. 视图创建
4. 触发器/存储过程

**SQL 关键字必背**：
```sql
-- 创建表
CREATE TABLE 表名 (
    列名 类型 PRIMARY KEY,
    列名 类型 NOT NULL,
    列名 类型 UNIQUE,
    列名 类型 DEFAULT 值,
    列名 类型 CHECK (条件),
    FOREIGN KEY (列名) REFERENCES 主表(主键)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

-- 复杂查询模板
SELECT 列, 聚合函数(列)
FROM 表1 [INNER|LEFT|RIGHT] JOIN 表2 ON 条件
WHERE 过滤条件
GROUP BY 列
HAVING 聚合条件
ORDER BY 列 [ASC|DESC]
LIMIT N;

-- 视图
CREATE VIEW 视图名 AS
SELECT ... FROM ... WHERE ...;
```

**子查询**：
- 标量子查询（返回单值）
- 列子查询（IN / NOT IN / ANY / ALL）
- 行子查询（= / <>）
- 表子查询（FROM 后）
- 关联子查询（EXISTS / NOT EXISTS）

#### ③ 必背：范式与函数依赖

**判定流程**：
1. 找出所有函数依赖
2. 求候选键（4 类划分法，见 ① 节口诀）
3. 判断范式

**🎯 范式判定口诀**：

> **"一看分、二看部、三看传、B 看主属性"**

| 范式 | 判定要点 | 口诀 | 消除什么 |
|------|---------|------|---------|
| **1NF** | 每个属性不可再分（原子性） | **一看分** | 复合属性 |
| **2NF** | 1NF + 非主属性**完全**依赖于码 | **二看部**（消除**部**分依赖） | 部分依赖 |
| **3NF** | 2NF + 非主属性**不传递**依赖于码 | **三看传**（消除**传**递依赖） | 传递依赖 |
| **BCNF** | 3NF + **主属性**也无部分/传递依赖（左侧均含码） | **B 看主属性** | 主属性的异常依赖 |

> 💡 **递进关系**：BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF（BCNF 最严格）

**模式分解**：
- **无损连接**：分解后通过自然连接能恢复（**必须**保证）
- **保持函数依赖**：分解后所有原依赖仍成立（**最好**保证）
- **分解原则**：**先保无损、再保依赖**（无损是底线，依赖是加分项）

**必考二元分解判定**：R 分解为 R1, R2 是无损连接 ⟺
- R1 ∩ R2 → R1 - R2，或
- R1 ∩ R2 → R2 - R1

> 💡 **口诀**：**"交集决定差集"** —— 两个子模式的**交集属性**能函数决定**任一子模式的差集属性**，即无损。

#### ④ 反规范化

**何时反规范化**：
- 查询性能瓶颈
- 报表/统计场景
- 读多写少

**常用手段**：
1. 增加冗余列（避免连接）
2. 增加派生列（预计算结果）
3. 重新组表（合并小表）
4. 分表（水平/垂直）

**反规范化代价**：数据冗余、维护一致性成本高 → 通过触发器/应用层维护

#### ⑤ 分布式数据库

**数据分片**：
- **水平分片**（按行）：按某列范围/哈希拆分
- **垂直分片**（按列）：按业务域拆分

**分库分表策略**：
- 分片键选择：访问频繁、分布均匀
- 分片算法：范围、哈希、一致性哈希

**分布式事务**：
- 2PC：准备 + 提交，强一致但阻塞
- 3PC：CanCommit + PreCommit + DoCommit
- TCC（Try-Confirm-Cancel）：业务补偿
- Saga：长事务，本地事务串联+补偿
- 最终一致性：消息表、事件溯源

**分布式数据库分布性透明**：
- 分片透明：用户不感知分片
- 复制透明：用户不感知副本
- 位置透明：用户不感知物理位置
- 逻辑透明：用户不感知数据模型差异

#### ⑥ 数据仓库与大数据

**OLTP vs OLAP**：
| 特性 | OLTP | OLAP |
|------|------|------|
| 用户 | 业务人员 | 决策者 |
| 操作 | 增删改查 | 复杂分析 |
| 数据量 | GB | TB-PB |
| 事务 | 短小、并发高 | 长、并发低 |
| 设计 | 规范化 | 反规范化（星型/雪花） |

**ETL**：抽取 → 转换 → 加载

**数据仓库建模**：
- **星型模型**：1 张事实表 + N 张维度表（最常用）
- **雪花模型**：维度表进一步规范化（节省空间但查询慢）
- **星座模型**：多张事实表共享维度

**数据湖 vs 数据仓库**：
| 维度 | 数据仓库 | 数据湖 |
|------|---------|--------|
| 数据 | 结构化 | 原始（结构化+半结构化+非结构化） |
| Schema | Schema-on-Write | Schema-on-Read |
| 用户 | 业务分析师 | 数据科学家 |
| 成本 | 高 | 低 |

**Lambda 架构**：批处理层 + 速度层 + 服务层（双路径）
**Kappa 架构**：仅流处理（简化）

### 4.3 题 3 答题模板

**典型 5 小问结构**：

**(1) 补充 E-R 图实体/联系（5 分）**
> 答题骨架：
> - 题干**名词** → 实体（矩形）/ 弱实体（双矩形）
> - 题干**动词** → 联系（菱形），加联系属性（如"成绩""日期"）
> - 必须标注**联系基数**：1:1 / 1:N / M:N

**(2) 写出关系模式（含主键、外键）（5-10 分）**
> 答题骨架：套口诀"**一对一爱合并、一对多向多放、多对多必独立**"
> 格式：`关系名(主键, 普通属性1, 普通属性2, 外键属性*)`
> 标记规则：**主键加下划线**，**外键标 `*`** 并在备注说明引用关系（如 教师号 → 教师(教师号)）

**(3) 指出候选键（5 分）**
> 答题骨架：套口诀"**L 必入、N 必入、R 必不入、LR 试探**"
> - Step 1：列出全部函数依赖
> - Step 2：把属性按 L/N/R/LR 四类划分
> - Step 3：L+N 集合求闭包验证；若不足则加入 LR 属性试探
> - Step 4：写出 `候选键 = {属性集合}` 并简述理由

**(4) SQL 编写（5-10 分）**
> 答题骨架：
> - **建表题**：`CREATE TABLE` + PK + FK + NOT NULL/UNIQUE/CHECK 约束齐全
> - **查询题**：按 `SELECT — FROM — JOIN — WHERE — GROUP BY — HAVING — ORDER BY — LIMIT` 标准骨架填充
> - **易错点**：聚合函数必配 `GROUP BY`；对聚合结果过滤用 `HAVING` 而非 `WHERE`

**(5) 范式判定与优化建议（5 分）**
> 答题骨架：
> - **范式判定**：套口诀"**一看分、二看部、三看传、B 看主属性**"
> - **模式分解**：套口诀"**交集决定差集**"判无损；优先级"**先无损、再保依赖**"
> - **优化方向**：①加索引（高选择性列）②反规范化（冗余列/派生列）③分库分表（水平/垂直）④读写分离
