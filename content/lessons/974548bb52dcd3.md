## 十八、近年新增热点补充（2024-2026 重点关注）

> 这些内容不一定每年大量出题，但常以 1-3 道选择题、案例题背景或论文题出现。复习策略：**会识别、会辨析、会写关键词**。

### 18.1 系统规划与企业架构（容易出概念辨析）

| 考点 | 核心要点 | 典型问法 |
|------|---------|---------|
| **BSP** | 企业系统规划，自上而下识别过程和数据，自下而上实施 | "先规划后实现"、"过程/数据类矩阵" |
| **CSF** | 关键成功因素法，从企业目标识别关键因素 | 问"围绕少数关键因素规划系统" |
| **SST** | 战略集合转化法，将组织战略转化为信息系统战略 | 问"使命、目标、战略集合" |
| **Zachman** | 企业架构二维分类框架，常见记法：6W × 6 视角 | 问"是什么/如何/哪里/谁/何时/为什么" |
| **TOGAF ADM** | 架构开发方法，循环迭代治理企业架构 | 问"架构愿景、业务架构、信息系统架构、技术架构" |

**TOGAF ADM 顺序速记**：
```
预备 → A架构愿景 → B业务架构 → C信息系统架构 → D技术架构
→ E机会与解决方案 → F迁移规划 → G实施治理 → H架构变更管理
```

- 架构治理：用流程和规范约束架构决策

### 18.3 Serverless / FaaS

**定义**：Serverless 是云计算执行模型，开发者关注函数和业务逻辑，底层服务器、扩缩容、运维由云平台管理。

**核心特征**：
- 事件驱动：HTTP、消息、对象存储、定时任务触发
- 自动弹性：按请求自动扩缩容
- 按量计费：按调用次数、执行时间、资源消耗计费
- 无状态函数：状态外置到数据库、缓存、对象存储

**优点**：降低运维成本、弹性伸缩快、适合突发流量和轻量任务。

**缺点**：冷启动、厂商锁定、长任务不适合、调试和可观测性复杂。

**适用场景**：图片处理、文件转码、Webhook、定时任务、秒杀削峰中的异步处理。

### 18.4 云原生数据库与存算分离

| 概念 | 要点 |
|------|------|
| **云原生数据库** | 面向云环境设计，强调弹性、自动运维、高可用 |
| **存算分离** | 计算节点与存储节点分离，计算可独立扩缩容 |
| **HTAP** | 同时支持 OLTP 与 OLAP，兼顾交易和分析 |
| **NewSQL** | 兼具关系模型、SQL、分布式扩展和强一致能力 |

**常考优点**：弹性伸缩、资源利用率高、容灾能力强、自动备份恢复、运维成本低。

**常考风险**：网络延迟、跨节点事务复杂、成本不可控、云厂商绑定。

### 18.5 信创 / 国产化 / 自主可控

**核心目标**：提升关键软硬件自主可控能力，降低供应链和安全风险。

**常见适配对象**：
- CPU：鲲鹏、飞腾、龙芯、兆芯
- 操作系统：麒麟、统信 UOS
- 数据库：达梦、人大金仓、OceanBase、openGauss
- 中间件：东方通、金蝶天燕、宝兰德

**考点关键词**：
- 兼容性适配：指令集、驱动、SQL 方言、中间件 API
- 数据迁移：结构迁移、数据校验、双写/灰度切换
- 性能验证：基准测试、压力测试、容量评估
- 安全合规：国密算法、等保、审计

### 18.7 端-边-云协同

**三层职责**：
- 端：采集、交互、轻量推理
- 边：就近计算、低延迟响应、数据预处理
- 云：全局调度、模型训练、海量存储、统一管理

**适用场景**：工业互联网、车联网、智慧城市、物联网、视频分析。

**优势**：降低时延、减少带宽、提升隐私保护和离线可用性。

#### 18.8.1 必拿计算题完整例题（带详解，每年至少 5 题这种）

**【例 1】子网划分（必考 1 题）**

> 题干：某公司分配到 IP 地址 **192.168.10.0/24**，需要划分 **5 个子网**，每个子网至少容纳 **25 台主机**，请问：
> ①子网掩码应该是多少？②每个子网可用主机数？③第 3 个子网的网络地址和广播地址？

**解题步骤**：
1. **算主机位**：每子网 ≥ 25 台 → 主机位 m 满足 `2^m - 2 ≥ 25` → m = 5（2^5-2=30 ≥ 25 ✓）
2. **算子网位**：5 个子网 → 子网位 n 满足 `2^n ≥ 5` → n = 3（2^3=8 ≥ 5 ✓）
3. **核验**：n + m = 3 + 5 = 8 ✓（C 类主机位总 8 位）
4. **子网掩码**：原 /24 + 借 3 位 = **/27**，即 `255.255.255.224`（224 = 11100000）
5. **块大小**：256 - 224 = **32**
6. **可用主机数**：2^5 - 2 = **30 台**
7. **子网列表**：
   - 子网 1：192.168.10.**0** / 27（广播 .31）
   - 子网 2：192.168.10.**32** / 27（广播 .63）
   - **子网 3：192.168.10.64 / 27（广播 192.168.10.95）** ← 答案
   - 子网 4：.96 ～ .127
   - 子网 5：.128 ～ .159

**速记口诀**：先算主机位（满足容量）→ 再算子网位（满足数量）→ 块大小 = 256 - 末段掩码值

**【例 2】关键路径（CPM，必考 1 题）**

> 题干：项目活动表如下，求关键路径和工期：
>
> | 活动 | 紧前活动 | 工期(天) |
> |------|---------|---------|
> | A | - | 5 |
> | B | - | 7 |
> | C | A | 6 |
> | D | A, B | 8 |
> | E | C | 4 |
> | F | D | 3 |
> | G | E, F | 5 |

**解题步骤**：
1. **画前趋图**（节点为活动）：
   ```
   开始 → A → C → E ↘
              ↓       G → 结束
              D → F ↗
        → B ↗
   ```
2. **正向算最早开始 ES / 最早结束 EF**（ES = 紧前活动 EF 的最大值，EF = ES + 工期）：

   | 活动 | ES | EF | 计算 |
   |------|----|----|----|
   | A | 0 | 5 | - |
   | B | 0 | 7 | - |
   | C | 5 | 11 | ES = A的EF=5 |
   | D | 7 | 15 | ES = max(A.EF=5, B.EF=7) = 7 |
   | E | 11 | 15 | ES = C.EF=11 |
   | F | 15 | 18 | ES = D.EF=15 |
   | G | 18 | 23 | ES = max(E.EF=15, F.EF=18) = 18 |

3. **工期 = G 的 EF = 23 天**
4. **逆向算 LS / LF**，**总时差 = LS - ES = 0** 的活动构成关键路径
5. **关键路径**：B → D → F → G（7+8+3+5 = 23 ✓）

**易错点**：当一个活动有多个紧前活动时，**取 EF 最大值**（不是平均）；关键路径可能有多条。

**【例 3】PERT 三点估算（必考 1 题）**

> 题干：某活动乐观工期 4 天、最可能 7 天、悲观 16 天。求期望工期和方差。

**公式**：
- 期望工期 E = (乐观 + 4 × 最可能 + 悲观) / 6
- 标准差 σ = (悲观 - 乐观) / 6
- 方差 σ² = ((悲观 - 乐观) / 6)²

**解**：
- E = (4 + 4×7 + 16) / 6 = (4 + 28 + 16) / 6 = **48 / 6 = 8 天**
- σ = (16 - 4) / 6 = **2**
- σ² = 4

**进阶**：若问"该活动 95% 概率能在多少天内完成"，按正态分布：
- 95% 置信区间 ≈ E + 1.645σ ≈ 8 + 1.645 × 2 ≈ **11.3 天**

**【例 4】哈夫曼树 WPL（高频）**

> 题干：给定权值 {3, 5, 7, 9, 11}，构造哈夫曼树并求 WPL（带权路径长度）。

**解题步骤**：
1. **每次取最小两个合并**：
   - Step 1：取 3、5 → 合并节点 8。剩余 {7, 8, 9, 11}
   - Step 2：取 7、8 → 合并节点 15。剩余 {9, 11, 15}
   - Step 3：取 9、11 → 合并节点 20。剩余 {15, 20}
   - Step 4：取 15、20 → 合并节点 35（根）。完成。

2. **画树并标层数**（根为第 1 层，叶子层数 = 路径长度）：
   ```
                  35
                /    \
              15      20
             /  \    /  \
            7    8  9   11
                / \
               3   5
   ```

3. **WPL 计算**（叶子权值 × 路径长度的累加）：
   - 3 × 4 = 12
   - 5 × 4 = 20
   - 7 × 2 = 14
   - 9 × 2 = 18
   - 11 × 2 = 22
   - **WPL = 12 + 20 + 14 + 18 + 22 = 86**

**速算技巧**：WPL = 所有**非叶子节点**权值之和 = 8 + 15 + 20 + 35 - 35（根不算）= 8 + 15 + 20 + ... 等等，正确公式应该是 **WPL = 所有非根的内部节点权值之和**。
- 内部节点：8、15、20、35
- WPL = 8 + 15 + 20 + 35 - 35（减去根，因为根的路径长度为 0）= **不行**
- **正确速算**：WPL = 所有合并产生的中间节点权值之和（不包括根） = 8 + 15 + 20 = **43**？也不对

> ⚠️ **直接套公式更稳**：WPL = Σ(叶子权值 × 路径长度)，按层数手算最不易错。

**【例 5】系统可靠性（串并联，必考 1 题）**

> 题干：一个系统由 3 个子系统串联组成，子系统 A 由 2 个并联模块（各 0.9）、子系统 B 单模块（0.85）、子系统 C 由 3 个并联模块（各 0.8）。求系统整体可靠度。

**公式**：
- 并联：R = 1 - (1-R1)(1-R2)...(1-Rn) （全坏才坏）
- 串联：R = R1 × R2 × ... × Rn （任一坏全坏）

**解**：
1. **子系统 A**（2 个并联）：R_A = 1 - (1-0.9)² = 1 - 0.01 = **0.99**
2. **子系统 B**：R_B = **0.85**
3. **子系统 C**（3 个并联）：R_C = 1 - (1-0.8)³ = 1 - 0.008 = **0.992**
4. **整体（串联）**：R = R_A × R_B × R_C = 0.99 × 0.85 × 0.992 ≈ **0.835**

**易错点**：先算每个子系统的并联可靠度，再串联相乘；不要颠倒先后。

**【例 6】海明码校验位数（必考 1 题）**

> 题干：要传输 8 位信息码，需要多少位海明校验位？校验位插在哪些位置？

**公式**：信息位 n，校验位 k 满足 `2^k ≥ n + k + 1`，**k 取最小满足值**。

**解**：
1. 试 k = 3：2³ = 8 < 8 + 3 + 1 = 12 ✗
2. 试 k = 4：2⁴ = 16 ≥ 8 + 4 + 1 = 13 ✓
3. **k = 4**（最小值）

**校验位插入位置**（从 1 开始编号，**2 的幂次位置**为校验位）：
- 位置 1 = 校验位 C1（2⁰）
- 位置 2 = 校验位 C2（2¹）
- 位置 3 = 数据位 D1
- 位置 4 = 校验位 C4（2²）
- 位置 5-7 = 数据位 D2, D3, D4
- 位置 8 = 校验位 C8（2³）
- 位置 9-12 = 数据位 D5, D6, D7, D8
- **总长度 = 12 位**

**速记口诀**：信息位 8 → 校验 4 位、信息 16 → 校验 5 位、信息 32 → 校验 6 位。

**【例 7】PV 操作（生产者-消费者基础题）**

> 题干：缓冲池有 N 个位置，1 个生产者、1 个消费者。请用信号量实现同步互斥。

**解**（三个信号量必备）：
```
信号量定义：
- mutex = 1       // 互斥访问缓冲区
- empty = N       // 空位数（资源信号量）
- full = 0        // 满位数（资源信号量）

生产者 Producer：
  while(true) {
    生产一个产品 item;
    P(empty);        // 申请空位（资源 P）
    P(mutex);        // 申请互斥锁（互斥 P）
    把 item 放入缓冲区;  // 临界区
    V(mutex);        // 释放互斥锁（互斥 V）
    V(full);         // 通知有满位（资源 V）
  }

消费者 Consumer：
  while(true) {
    P(full);         // 申请满位
    P(mutex);        // 申请互斥锁
    从缓冲区取一个 item;
    V(mutex);        // 释放互斥锁
    V(empty);        // 通知有空位
    消费 item;
  }
```

**核心口诀**：**"资源 P → 互斥 P → 临界区 → 互斥 V → 资源 V"**——顺序不能颠倒，否则可能死锁！

**死锁分析**：若把 `P(mutex)` 和 `P(empty)` 顺序颠倒：
- 生产者先获得 mutex，再 P(empty) 发现没空位被阻塞 → 抱着锁睡
- 消费者要释放 V(empty) 需要先 P(mutex) → 拿不到锁
- → **死锁**

### 18.9 通信系统架构（补充）

**高频问法**：协议选型、低时延保障、网络可靠性、接入层与控制层职责划分。

| 概念 | 速记要点 |
|------|---------|
| **QoS** | 关注时延、抖动、丢包率、吞吐量，核心流量优先保障 |
| **端到端时延** | 传输时延 + 排队时延 + 处理时延，排队和拥塞最易导致突增 |
| **高可用链路** | 双链路/主备切换/链路探测，目标是故障快速收敛 |
| **协议适配** | 设备接入常用 MQTT/CoAP，业务接口常用 HTTP/gRPC |

**易错点**：
- 只谈带宽不谈时延和抖动（QoS 不完整）
- 把高吞吐和低时延简单等同（并不总成立）
- 只写协议名称，不写适用场景和约束

### 18.10 可靠性分析方法（补充）

| 方法 | 作用 | 常见考法 |
|------|------|---------|
| **FTA（故障树）** | 自顶向下分析故障原因路径 | 给顶事件，问中间/底事件关系 |
| **FMEA** | 自底向上分析失效模式及影响 | 问如何识别高风险失效点 |
| **RBD（可靠性框图）** | 通过串并联系统计算可靠性 | 结合串并联公式计算整体可靠度 |

**速记**：
- FTA：先有故障结果，再追溯原因。
- FMEA：先看组件失效，再看系统影响。
- RBD：把系统结构抽象成可计算模型。
