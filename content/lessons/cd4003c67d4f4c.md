## 十、近年新增案例热点补充

> 新热点通常不会脱离架构师主线，本质仍然考：**质量属性、架构取舍、技术选型、风险与应对**。

### 10.1 Serverless 架构案例

**常见题干特征**：
- 业务流量波动大，存在明显峰谷
- 希望降低运维成本、按量付费
- 由 HTTP 请求、消息、文件上传、定时任务触发

**答题关键词**：
- 事件驱动、函数计算、API 网关、BaaS、自动弹性、按量计费
- 状态外置：数据库、缓存、对象存储
- 可观测性：日志、指标、链路追踪

**优点**：
1. 自动扩缩容，适合突发流量
2. 无需管理服务器，降低运维成本
3. 按实际调用付费，资源利用率高
4. 便于快速开发轻量任务

**风险与应对**：
1. 冷启动影响响应时间 → 预热、保留实例、拆分轻量函数
2. 厂商锁定 → 采用标准事件模型、隔离云厂商 SDK
3. 函数无状态 → 状态外置到 Redis/数据库/对象存储
4. 调试困难 → 完善日志、链路追踪和本地模拟环境

### 10.2 云原生数据库 / 存算分离案例

**常见题干特征**：
- 数据量增长快，读写压力不均衡
- 希望计算资源和存储资源独立扩展
- 要求自动备份、容灾、高可用、低运维成本

**答题关键词**：
- 存算分离、弹性扩缩容、多副本、自动故障转移、备份恢复
- HTAP、NewSQL、分布式事务、全局一致性

**方案模板**：
1. 存储层采用分布式共享存储，多副本保证可靠性
2. 计算层无状态化，按业务压力横向扩展
3. 读写分离和只读副本承担读压力
4. 自动备份、跨可用区部署，满足 RPO/RTO
5. 通过监控慢 SQL、连接数、锁等待优化性能

**风险与应对**：
- 跨节点事务复杂 → 控制事务边界，必要时采用最终一致
- 网络延迟增加 → 就近部署、缓存热点数据
- 成本不可控 → 设置资源配额、自动伸缩阈值和成本告警

### 10.3 信创 / 国产化适配案例

**常见题干特征**：
- 政务、金融、能源等关键行业
- 要求国产 CPU、操作系统、数据库、中间件替换
- 关注自主可控、安全合规、平滑迁移

**答题框架**：
1. **兼容性评估**：梳理硬件、OS、数据库、中间件、第三方组件依赖
2. **分层适配**：基础设施、数据层、应用层、接口层逐层替换
3. **数据迁移**：结构迁移、数据校验、双写或灰度切换
4. **性能验证**：基准测试、压力测试、容量评估
5. **安全合规**：国密改造、等保要求、日志审计
6. **灰度上线**：先非核心业务，再核心业务，保留回退方案

**常见风险**：
- SQL 方言不兼容
- 驱动和中间件 API 差异
- 性能下降
- 第三方组件不支持国产环境

### 10.4 端-边-云协同案例

**常见题干特征**：
- 物联网、工业互联网、视频分析、车联网
- 要求低延迟、断网可用、减少带宽占用
- 终端数量多，数据实时性要求高

**职责划分**：
| 层次 | 职责 |
|------|------|
| 端 | 数据采集、设备控制、轻量推理 |
| 边 | 实时处理、协议转换、缓存、局部决策 |
| 云 | 全局调度、模型训练、海量存储、统一运维 |

**答题要点**：
- 边缘节点就近处理，降低时延
- 云端统一管理模型、策略和设备
- 边云断连时本地自治，恢复后数据同步
- 采用 MQTT/CoAP 等轻量协议接入设备

### 10.5 AI 集群 / 高性能网络案例（了解型）

**常见题干特征**：
- 大模型训练、AI 推理平台、GPU/NPU 集群
- 关注训练效率、网络拥塞、节点故障恢复

**关键词**：
- GPU/NPU、RDMA、RoCE、AllReduce、高速互联、弹性调度
- 容器化调度、资源隔离、监控告警、故障迁移

**答题方向**：
1. 计算层：GPU/NPU 池化，按任务调度资源
2. 网络层：RDMA/RoCE 降低通信延迟
3. 存储层：高吞吐并行文件系统或对象存储
4. 调度层：Kubernetes + AI 调度插件
5. 可靠性：节点健康检测、任务重试、检查点恢复

### 10.6 性能测试与性能优化案例

**常见题干特征**：
- 要求设计性能测试方案
- 关注响应时间、吞吐量、并发数、资源利用率

**测试类型**：
- 负载测试：验证预期负载下能否满足指标
- 压力测试：找系统极限和瓶颈
- 容量测试：评估最大用户数/数据量
- 稳定性测试：长时间运行观察资源泄漏

**指标**：
- 平均响应时间、P95/P99 响应时间
- TPS/QPS、并发用户数
- CPU、内存、磁盘 I/O、网络 I/O
- 错误率、超时率

**优化套路**：
前端 CDN/压缩 → 网关限流 → 应用异步/线程池 → 缓存 → 数据库索引/读写分离 → 水平扩展。

### 10.7 通信系统架构案例（补强）

**常见题干特征**：
- 出现 5G/工业网关/边缘站点/专网改造等背景
- 要求兼顾低时延、高可靠、可扩展与安全隔离
- 关注协议适配、链路冗余、QoS、故障切换

**答题关键词**：
- 分层设计（接入层/传输层/控制层/应用层）
- 协议适配（MQTT/CoAP/HTTP/TCP/UDP）
- QoS（时延、抖动、丢包率、带宽保障）
- 高可用（双链路、主备切换、链路探活）
- 安全（TLS、设备认证、访问控制、审计）

**标准答题骨架**：
1. **架构分层**：说明各层职责，避免耦合到单一协议或单一厂商设备。
2. **接入与协议**：端侧按场景选择轻量协议，网关统一协议转换与数据标准化。
3. **传输与可靠性**：关键链路双活/主备，心跳探测+自动切换，消息重传与去重。
4. **性能与 QoS**：核心业务流量优先级更高，控制类报文优先保障时延。
5. **安全与运维**：设备身份认证、链路加密、日志审计、统一监控告警。

### 10.8 层次式/信息系统架构案例（补强）

**常见题干特征**：
- 需要从"业务-应用-数据-技术"视角做整体设计
- 要求说明为什么采用分层，以及层间交互规则
- 经常考察扩展性、可维护性、性能与一致性的权衡

**信息系统四层速记**：
| 层次 | 核心职责 | 常见输出 |
|------|---------|---------|
| 业务架构 | 业务能力、流程、组织职责 | 业务能力图、流程图 |
| 应用架构 | 系统边界、服务协作、接口 | 应用清单、接口矩阵 |
| 数据架构 | 主数据、数据流、共享与治理 | 主题域、数据模型 |
| 技术架构 | 部署、网络、中间件、安全与运维 | 部署图、技术栈 |

**层次式架构答题要点**：
- 只允许相邻层调用，禁止跨层直连数据库
- 将横切关注点（鉴权、日志、缓存、限流）沉淀为公共能力
- 高变更业务逻辑与稳定技术能力解耦，提升可维护性
- 对性能敏感链路可采用"受控旁路"，但必须说明边界和治理措施
