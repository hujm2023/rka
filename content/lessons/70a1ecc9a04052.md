### 21.1 RAID 存储级别对比（必考 1 题）

| 级别 | 最少盘数 | 利用率 | 容错盘数 | 读写性能 | 关键特征 |
|------|---------|--------|---------|---------|---------|
| **RAID 0** | 2 | 100% | 0 | 读写最快 | 条带化(Stripe)，无冗余 |
| **RAID 1** | 2 | 50% | 镜像盘数-1 | 读快/写正常 | 镜像(Mirror) |
| **RAID 2** | - | - | - | - | 海明码校验（已淘汰） |
| **RAID 3** | 3 | (n-1)/n | 1 | 大文件读快 | 位级奇偶校验，独立校验盘 |
| **RAID 4** | 3 | (n-1)/n | 1 | 写有瓶颈 | 块级奇偶校验，独立校验盘 |
| **RAID 5** | 3 | (n-1)/n | 1 | 读快/写中 | 分布式奇偶校验（**最常用**） |
| **RAID 6** | 4 | (n-2)/n | 2 | 写最慢 | 双奇偶校验 |
| **RAID 10**（1+0） | 4 | 50% | 多盘（每组1） | 读写都快 | 先镜像后条带（**安全+性能**） |
| **RAID 01**（0+1） | 4 | 50% | 较差 | 较好 | 先条带后镜像（**不推荐**） |

**速记口诀**：
- RAID 0 快不安全、RAID 1 安全不快、RAID 5 折中、RAID 10 又快又安全（最贵）
- 容量计算：RAID 5 用 n 块 m GB 盘 → 可用容量 = (n-1)×m GB

### 21.2 计算机体系结构补强

**冯·诺依曼 vs 哈佛体系**：

| 维度 | 冯·诺依曼 | 哈佛体系 |
|------|----------|---------|
| 存储 | 程序与数据**共用**存储 | 程序与数据**独立**存储 |
| 总线 | 一组 | 两组 |
| 速度 | 较慢（瓶颈） | 较快 |
| 应用 | 通用 CPU | DSP、ARM Cortex-M、嵌入式 |

**寻址方式（必考辨析）**：

| 方式 | 操作数位置 | 速度 | 灵活性 |
|------|-----------|------|--------|
| **立即寻址** | 指令中直接给出 | 最快 | 最差（值固定） |
| **直接寻址** | 指令给出操作数地址 | 快 | 一般 |
| **间接寻址** | 指令给出地址的地址 | 慢 | 灵活 |
| **寄存器寻址** | 寄存器中 | 最快 | 最好 |
| **寄存器间接寻址** | 寄存器中的地址 | 较快 | 较好 |
| **相对寻址** | PC + 偏移量 | 较快 | 支持位置无关代码 |
| **变址寻址** | 变址寄存器 + 偏移 | 较快 | 适合数组 |
| **基址寻址** | 基址寄存器 + 偏移 | 较快 | 适合多道程序 |

**中断处理 5 步**：保存现场 → 分析中断源 → 执行中断服务程序 → 恢复现场 → 中断返回

### 21.3 网络协议补强

**HTTP/1.1 vs HTTP/2 vs HTTP/3 对比（近年热点）**：

| 维度 | HTTP/1.1 | HTTP/2 | HTTP/3 |
|------|----------|--------|--------|
| 传输层 | TCP | TCP | **QUIC（基于 UDP）** |
| 多路复用 | 不支持（队头阻塞） | 支持 | 支持（无队头阻塞） |
| 头部压缩 | 无 | HPACK | QPACK |
| 服务器推送 | 无 | 支持 | 支持 |
| 加密 | 可选 | 实际强制 | 强制 |

**IPv6 地址类型（必考辨析）**：

| 类型 | 含义 | 对应 IPv4 |
|------|------|----------|
| **单播 Unicast** | 一对一 | 单播 |
| **任播 Anycast** | 一对最近（多个接口共享地址，发送给最近的） | IPv4 无 |
| **组播 Multicast** | 一对多组成员 | 组播 |
| **～广播** | IPv6 **取消广播**，用组播代替 | 广播 |

**SDN / NFV**：
- **SDN（软件定义网络）**：控制平面与数据平面分离，集中控制（OpenFlow 协议）
- **NFV（网络功能虚拟化）**：用虚拟机/容器实现网络设备功能（防火墙、负载均衡）

### 21.5 DFD（数据流图）与数据字典（案例必考）

**DFD 四要素**：

| 符号 | 含义 | 命名 |
|------|------|------|
| 外部实体（方框） | 系统外的人/组织/系统 | 名词 |
| 加工/处理（圆圈） | 对数据的变换 | 动词+宾语 |
| 数据流（带箭头线） | 数据流动方向 | 名词 |
| 数据存储（双横线） | 存储的静态数据 | 名词 |

**分层 DFD**：
- 顶层（Context Diagram）：整个系统作为 1 个加工
- 0 层：将顶层分解为若干主要加工
- 详细层：继续逐层细化（每层 ≤ 7±2 个加工）

**平衡原则**：
- 父图与子图的输入输出数据流必须一致
- 同名数据流方向必须一致

**数据字典 DD 的 4 类条目**：
1. **数据项**：最小单位（如 学号）
2. **数据结构**：若干数据项组合（如 学生信息）
3. **数据流**：数据结构在系统中流动
4. **数据存储**：静态保留的数据（对应数据库表）

**判定表 vs 判定树**：
- 判定表：行=条件/动作，列=规则；适合多条件组合
- 判定树：树形展开；直观但条件多时膨胀

### 21.6 嵌入式系统补强（必考 2-4 题）

**嵌入式微处理器分类**：

| 类型 | 全称 | 特点 | 应用 |
|------|------|------|------|
| **MPU** | 微处理器 | 通用，性能高 | 高端嵌入式（ARM Cortex-A） |
| **MCU** | 微控制器 | 集成 ROM/RAM/外设 | 单片机（51、STM32） |
| **DSP** | 数字信号处理器 | 哈佛结构、乘加快 | 信号处理、音视频 |
| **SoC** | 片上系统 | 一片集成完整系统 | 手机、IoT |
| **NP** | 网络处理器 | 高速包处理 | 路由器、交换机 |

**嵌入式系统软件层次**：
```
应用软件层 ← 业务应用
─────────────
中间件层  ← 通信、消息、数据库中间件
─────────────
RTOS 内核 ← 任务调度、内存、同步通信
─────────────
BSP 板级支持包 ← 设备驱动、HAL 硬件抽象
─────────────
硬件层    ← CPU + 存储 + I/O 外设
```

**RM 可调度判据例题**：

> 例：3 个周期任务 T1(C=20,T=100), T2(C=30,T=150), T3(C=80,T=300)，能否用 RM 调度？

- 利用率 U = 20/100 + 30/150 + 80/300 = 0.2 + 0.2 + 0.267 = **0.667**
- RM 判据：U ≤ 3×(2^(1/3)-1) = **0.779**
- 结论：0.667 < 0.779 ∴ **可调度**

**优先级反转例题**：

> 任务 H（高）、M（中）、L（低）共享资源 R：
> 1. L 先锁 R 运行；
> 2. H 抢占 L，请求 R 被阻塞；
> 3. M 抢占 L 运行（与 R 无关）；
> 4. H 被 M 间接阻塞（**优先级反转**发生）

**解决方案**：
- **优先级继承协议（PIP）**：L 临时继承 H 的优先级 → M 无法抢占 L → L 尽快释放 R
- **优先级天花板协议（PCP）**：L 一锁 R 就提升到该资源的最高优先级（天花板）

### 21.7 架构方法论补强（ABSD / AOP / MDA / CBSD）

**ABSD（基于体系结构的软件设计）6 步骤**：

| 步骤 | 任务 | 输出 |
|------|------|------|
| 1. 架构需求 | 标识构件、获取需求 | 需求规格、ASR |
| 2. 架构设计 | 提出方案、迭代 | 架构图、设计说明 |
| 3. 架构文档化 | 编写架构说明书 + 测试规格 | 文档 |
| 4. 架构复审 | 由专家评审 | 评审报告 |
| 5. 架构实现 | 按架构构造系统 | 可运行系统 |
| 6. 架构演化 | 适应需求变化 | 新版本架构 |

**核心特征**：自顶向下、递归细化、视角与视图

**AOP（面向方面编程）5 大核心概念**（2019 真题）：

| 概念 | 英文 | 含义 |
|------|------|------|
| **切面** | Aspect | 横切关注点的模块化（如日志、事务） |
| **连接点** | Join Point | 程序执行中可以插入切面的点 |
| **切入点** | Pointcut | 匹配连接点的表达式 |
| **通知** | Advice | 在连接点上执行的动作（前置/后置/环绕/异常/最终） |
| **织入** | Weaving | 将切面应用到目标对象并创建代理对象的过程；分编译时织入（AspectJ）和运行时织入（Spring AOP） |

> ⚠️ 易错点：**引入(Introduction)** 是 Advice 的一种特殊形式（向已有类添加新方法/字段），不是 5 大核心概念之一。2019 真题考的就是上述 5 个标准概念，**不要把"引入"当作核心概念答**。

**AOP 应用场景**：日志、事务、安全、缓存、监控（Spring AOP）

**MDA（模型驱动架构）三层模型**：

| 模型 | 全称 | 含义 |
|------|------|------|
| **CIM** | 计算无关模型 | 业务模型，与计算实现无关 |
| **PIM** | 平台无关模型 | 系统模型，与平台无关 |
| **PSM** | 平台相关模型 | 针对具体平台的实现模型 |

**转换路径**：CIM → PIM → PSM → 代码（自动生成）

**基于复用 vs CBSD（基于构件的开发）**：

| 维度 | 软件复用 | CBSD |
|------|---------|------|
| 复用对象 | 任意层次（代码/设计/需求） | 标准构件 |
| 复用方式 | 拷贝、参数化、继承 | 组装 |
| 关键 | 复用库 | 构件规约、接口、组装机制 |

**构件组装的三种方式**：
- **黑盒组装**：只通过接口，不修改构件
- **白盒组装**：可见且可修改源码
- **灰盒组装**：可见但仅修改部分（如扩展点）

### 21.8 大数据与新一代信息技术

**Hadoop 生态（高频）**：

| 组件 | 定位 |
|------|------|
| **HDFS** | 分布式文件系统（NameNode + DataNode） |
| **MapReduce** | 分布式计算框架（已被替代） |
| **YARN** | 资源调度（ResourceManager + NodeManager） |
| **HBase** | 列式 NoSQL 数据库（基于 HDFS） |
| **Hive** | SQL on Hadoop，类 SQL 查询离线数仓 |
| **Spark** | 内存计算引擎（比 MR 快 100 倍） |
| **Flink** | 流处理为主，真正流批一体 |
| **Kafka** | 分布式消息队列 |
| **Zookeeper** | 协调服务（选举、配置） |

**Spark vs Flink**：
- Spark：批为主，流是"微批"（Spark Streaming）
- Flink：**流为主**，批是"有界流"，真正低延迟

**区块链**（V2.0 新增）：

| 概念 | 要点 |
|------|------|
| **本质** | 去中心化分布式账本 |
| **共识机制** | PoW（工作量证明，比特币）、PoS（权益证明，以太坊2）、PBFT（实用拜占庭，联盟链）、DPoS |
| **智能合约** | 自动执行的代码，部署在链上 |
| **类型** | 公有链（比特币）、联盟链（Hyperledger Fabric）、私有链 |
| **特性** | 不可篡改、可追溯、去中心化、匿名性 |

**数字孪生**（2023 案例题考点）：
- **四要素**：物理实体、虚拟实体、数据、连接
- **应用**：智能制造、智慧城市、工业互联网

**CDN 工作原理**：
- 内容分发：源站 → 边缘节点缓存
- 智能调度：基于 DNS 解析返回最近节点
- 回源：缓存未命中时回源站拉取

### 21.9 设计模式 GRASP 9 原则（少考但有出现）

### 21.10 PKI 与 CBAM 计算补强

**X.509 数字证书核心字段**：
- 版本号、序列号、签名算法、颁发者(CA)、有效期、主体（持有者）、主体公钥、CA 数字签名

**CA 信任链验证流程**：
1. 检查证书有效期
2. 验证 CA 签名（用上级 CA 公钥）
3. 检查证书撤销列表 CRL 或 OCSP
4. 检查主体身份匹配

**CBAM 计算示例**：

> 场景 A：投资 100 万改造缓存，预期年节省 300 万 → ROI = (300-100)/100 = **200%**
> 场景 B：投资 200 万异地多活，预期年节省 500 万 → ROI = (500-200)/200 = **150%**
> 决策：A 的 ROI 高，优先实施 A

**CBAM 步骤**：场景整理 → 优先级 → 收益估算 → 成本估算 → ROI 计算 → 决策

**等保 2.0 五级差异（高频送分）**：

| 等级 | 名称 | 适用 |
|------|------|------|
| 一级 | 用户自主保护 | 一般信息系统 |
| 二级 | 系统审计保护 | 一般企业系统 |
| **三级** | **安全标记保护** | **政府、金融、医疗等关键信息系统**（最常考） |
| 四级 | 结构化保护 | 重要国家系统 |
| 五级 | 访问验证保护 | 极端重要系统 |

### 21.11 RUP 与软件过程补强

**RUP（统一软件开发过程）4 阶段**：

| 阶段 | 重点 | 里程碑 |
|------|------|--------|
| **初始** Inception | 业务建模、范围 | 生命周期目标 |
| **细化** Elaboration | 架构基线、风险消除 | 生命周期架构 |
| **构造** Construction | 编码实现、测试 | 初始运行能力 |
| **移交** Transition | 部署、用户培训 | 产品发布 |

**RUP 9 个工作流**（前 6 个核心工作流 + 后 3 个支持工作流）：
- 核心：业务建模、需求、分析与设计、实现、测试、部署
- 支持：配置与变更管理、项目管理、环境

**RUP 三大特征**：用例驱动、以架构为中心、迭代与增量

**净室软件工程**：基于数学和统计学，强调缺陷预防，"零缺陷"目标
- 核心技术：形式化规约、统计测试、增量开发

### 21.13 专业英语真题样题（参考练习）

> "Microservices architecture is an approach in which a single application is composed of many ___ services."

- **immutable infrastructure**（不可变基础设施）
