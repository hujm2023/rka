## 六、软件工程（5-8题）

### 6.1 软件开发模型（必考辨析）

| 模型 | 特点 | 适用 |
|------|------|------|
| 瀑布 | 线性、文档驱动、需求稳定 | 需求明确 |
| V 模型 | 测试与开发对应 | 强调测试 |
| 增量 | 分批交付 | 核心功能优先 |
| 演化/迭代 | 迭代细化 | 需求模糊 |
| 原型 | 快速验证需求 | 需求获取 |
| **螺旋** | **瀑布+原型+风险分析** | **大型高风险** |
| 喷泉 | 面向对象、迭代无缝 | OO 项目 |
| RUP | 用例驱动、迭代、架构为中心 | 大型软件 |
| **敏捷** | 个体>过程、可工作软件>文档、响应变化>计划 | 需求变化频繁 |
| RAD | 快速原型+组件化 | 中小型 |

**敏捷家族**：XP（极限编程）、Scrum、FDD、Crystal、ASD、DSDM

**XP 实践**：结对编程、测试驱动开发(TDD)、持续集成、小版本发布、简单设计、重构、集体代码所有制

### 6.2 需求工程

**需求分类**：
- 业务需求 → 用户需求 → 系统需求
- 功能需求 + 非功能需求（性能/安全/可用） + 设计约束

**需求获取**：访谈、问卷、原型、观察、头脑风暴、用例
**需求分析建模**：DFD、E-R、状态图、用例图

**质量功能部署 QFD**：常规需求、期望需求、意外需求

### 6.3 测试

**白盒覆盖（强弱排序）**：
语句 < 判定（分支） < 条件 < 判定/条件 < 条件组合 < 路径

> 📌 关于 **MC/DC（修正条件/判定覆盖）**：MC/DC 是 DO-178B（航空软件）和 ISO 26262（汽车功能安全）等行业标准的强制要求，覆盖强度介于"条件覆盖"与"条件组合覆盖"之间，但**与条件组合覆盖维度不完全可比**（MC/DC 要求每个条件**独立影响**判定结果，更聚焦"必要测试"而非"穷举"）。考试中如果出现 MC/DC 选项，记忆为"接近条件组合覆盖但更精简"即可。

**判定 vs 条件 vs 判定/条件 速记**：
- **判定（分支）覆盖**：让每个判定的真假分支至少各执行一次
- **条件覆盖**：让每个判定中**每个原子条件**的真假至少各取一次
- **判定/条件覆盖**：同时满足判定覆盖 + 条件覆盖
- **条件组合覆盖**：让每个判定中**所有条件取值的组合**至少各出现一次（2^n 种组合）

**黑盒方法**：等价类、边界值、错误推测、因果图、判定表、正交试验

**测试阶段**：
- **单元测试**：白盒为主，模块功能、接口、局部数据、边界、错误处理
- **集成测试**：自顶向下（用桩）、自底向上（用驱动）、三明治
- **确认测试**：α(开发场)、β(用户场)
- **系统测试**：恢复、安全、强度、性能、可用性、安装

**McCabe 环路复杂度** = 边数 - 节点数 + 2 = 判定节点数 + 1

### 6.4 软件维护

**四种类型**：
- **改正性 Corrective**（约 17-21%）：修 bug
- **适应性 Adaptive**（约 18-25%）：适应环境
- **完善性 Perfective**（约 50-60%）：新需求 ★**占比最大**（Lientz & Swanson 数据 65%，国内教程多用 50%）
- **预防性 Preventive**（约 4%）：防患未然

> ⚠️ 易错点：考题问"软件维护中占比最大的是"——答**完善性**。
> 不同教材给出的具体百分比略有差异（清华版常用 50%，国际经典文献为 60-65%），但占比最大的是完善性这一结论是一致的。

**可维护性子特性**：易分析性、易改变性、稳定性、易测试性、可移植性

### 6.5 软件复用与逆向工程

**复用层次**：代码 → 设计 → 分析 → 测试用例 → 需求

**逆向工程层次**（从低到高，抽象度递增）：
实现级 → 结构级 → 功能级 → 领域级

### 6.6 项目管理

**进度管理（PERT/CPM）**：
- 正向计算：最早开始、最早结束
- 反向计算：最晚开始、最晚结束
- 总时差 = LS - ES = LF - EF
- **关键路径**：总时差为 0 的路径，最长路径

**PERT 三点估算**：期望 = (乐观 + 4×最可能 + 悲观) / 6
方差 = ((悲观 - 乐观)/6)²

**成本估算**：
- COCOMO：组织型/嵌入型/半独立型，三层（基本/中级/详细）
- COCOMO II：应用组装、早期设计、后体系结构
- 功能点 FPA：与具体语言无关

**风险管理**：识别 → 评估 → 规划 → 控制
- 风险敞口 RE = 概率 × 损失

**CMM/CMMI 等级**（必考，注意 CMM 与 CMMI 命名不同）：

| 等级 | **CMM**（已淘汰，1991-2003） | **CMMI**（现行，2002 至今） | 核心特征 |
|------|------------------------------|------------------------------|---------|
| L1 | 初始级 Initial | 初始级 Initial | 混乱、依赖个人英雄 |
| L2 | **可重复级** Repeatable | **已管理级** Managed | 基本项目管理流程 |
| L3 | 已定义级 Defined | 已定义级 Defined | 标准化、组织级过程 |
| L4 | 已管理级 Managed | **量化管理级** Quantitatively Managed | 量化目标 + 统计控制 |
| L5 | 优化级 Optimizing | 优化级 Optimizing | 持续过程改进 |

> ⚠️ **关键差异**：CMM L2 叫"**可重复级**"，CMMI L2 才叫"**已管理级**"。考题中若题干用"CMM"则用旧名，用"CMMI"则用新名。**目前考试以 CMMI 命名为主**（CMM 已被 CMMI 取代），但选择题偶尔会用 CMM 旧名作干扰。

**CMMI 表示法**：阶段式（同 CMM 5级）/ 连续式（6级：0-不完整, 1-已执行, 2-已管理, 3-已定义, 4-量化管理, 5-优化）

### 6.7 软件度量

- 规模：LOC（代码行）、FP（功能点）
- 复杂度：McCabe 环路复杂度
- 质量：缺陷密度、平均故障间隔
- 生产率：LOC/人月、FP/人月
