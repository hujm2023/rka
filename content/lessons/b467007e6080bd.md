## 十三、查漏补缺案例补强专题

> 针对历年真题中**易丢分、易遗漏、易答偏**的高价值案例考点补强。每个专题给出**关键步骤 + 标准答案骨架 + 易错点**。

### 13.1 数据库设计完整 6 步骤（题 3 必备）

> 案例题 3 常出"完整数据库设计案例"，要求按规范步骤作答。

| 步骤 | 任务 | 输出物 | 答题关键词 |
|------|------|--------|-----------|
| ① **需求分析** | 收集业务流程与数据需求 | 需求规格、**DFD**、**数据字典** | 业务调研、用户访谈 |
| ② **概念结构设计** | 抽象业务实体与关系，与 DBMS 无关 | **E-R 图** | 实体、属性、联系、聚合 |
| ③ **逻辑结构设计** | E-R 转关系模式，按范式优化 | 关系模式（含主键/外键） | 1NF→3NF/BCNF、规范化 |
| ④ **物理结构设计** | 选择存储结构与访问路径 | 索引、分区、表空间 | B+树索引、聚簇 |
| ⑤ **数据库实施** | 建库建表、初始数据加载 | DDL、初始数据 | 建表、约束、应用接入 |
| ⑥ **运行与维护** | 监控、调优、备份 | 监控报告、备份策略 | 慢查询、备份恢复、安全 |

**典型考法**：
- 给出业务描述 → 补 E-R 图缺失实体/联系
- 给出 E-R → 写出关系模式（标主键、外键、候选键）
- 给出关系模式 → 判断范式、给出分解
- 给出场景 → 编写 SQL（含联接、聚合、子查询）

### 13.2 优先级反转完整例题（题 5 嵌入式必备）

**题干样式**：
> 任务 H（优先级 10）、M（优先级 5）、L（优先级 1）共享互斥资源 R：
> - t=0: L 启动，锁定 R，开始执行
> - t=2: H 就绪，抢占 L
> - t=2.5: H 请求 R，被阻塞，L 继续持锁运行
> - t=3: M 就绪，抢占 L 执行（与 R 无关）
> 分析存在什么问题，提出解决方案。

**标准答案骨架**：

**(1) 问题诊断**：
> 发生**优先级反转**：高优先级 H 因等待 L 释放 R 而阻塞，但中优先级 M 抢占了 L 的执行，导致 H 间接被 M 阻塞，违反优先级调度原则，可能引起 H 错过截止期。

**(2) 解决方案对比**：

| 协议 | 机制 | 优缺点 |
|------|------|--------|
| **优先级继承协议 PIP** | L 锁 R 期间，若被 H 阻塞，则 L **临时继承** H 的优先级 → M 无法抢占 L → L 尽快释放 R | 实现简单，但可能链式继承 |
| **优先级天花板协议 PCP** | L 一获得 R 就立即提升到该资源的**最高使用者优先级**（天花板） | 防止死锁与链式继承，但要预知最高优先级 |

**(3) 工程建议**：
- 缩短临界区
- 避免嵌套加锁
- 使用支持 PIP 的 RTOS（VxWorks、FreeRTOS）

### 13.3 AOP（面向方面编程）案例补强（2019 真题）

**典型题干**：日志、安全、事务等横切关注点散落在多个模块中，导致代码重复且难维护，如何重构？

**标准答案骨架**：

**(1) 识别问题**：横切关注点（Cross-Cutting Concerns）跨越多个模块，违反单一职责原则。

**(2) AOP 解决方案**：
- **切面 Aspect**：把日志/事务/安全模块化为切面
- **连接点 Join Point**：方法调用、方法执行
- **切入点 Pointcut**：用表达式匹配需要织入的方法（如 `execution(* com.xx.service.*.*(..))`）
- **通知 Advice**：前置（@Before）、后置（@After）、环绕（@Around）、返回后（@AfterReturning）、异常后（@AfterThrowing）
- **织入 Weaving**：编译时织入（AspectJ）/ 运行时织入（Spring AOP 动态代理）

**(3) 效果**：
- 业务代码无侵入
- 横切关注点集中维护
- 符合开闭原则与单一职责

**(4) 与代理模式关系**：Spring AOP 底层 = JDK 动态代理（接口）或 CGLIB（无接口）

### 13.4 架构演化与治理案例补强

**典型题干**：系统经多年迭代后出现性能下降、模块耦合严重、技术债累积，如何治理？

**标准答案骨架**：

**(1) 现状评估**：
- **架构腐蚀**指标：模块耦合度、重复代码率、变更失败率、平均修复时间 MTTR
- **技术债清单**：按影响范围 × 修复成本分级

**(2) 治理机制**：

| 措施 | 具体做法 | 度量指标 |
|------|---------|---------|
| **ADR 决策留痕** | 关键技术选型写 Architecture Decision Record | ADR 数量 |
| **架构评审** | 重大变更须经架构委员会评审 | 评审通过率 |
| **质量门禁** | CI 中加入静态扫描、单测覆盖率 | 代码质量分数 |
| **技术债台账** | 列入版本计划逐步偿还 | 季度清偿率 |
| **运行度量** | 监控变更失败率、MTTR | 故障数下降率 |

**(3) 演化路径**：
- 识别核心可重构域 → 灰度迁移 → 旧模块下线 → 持续监控

**(4) 典型答题句**：
> "为避免长期演进中的架构腐蚀，我建立了 ADR 机制 + 架构评审 + 质量门禁 + 技术债管理 + 度量闭环的五位一体治理体系，季度技术债清偿率提升 20%，重大故障下降 50%。"

### 13.5 企业架构（TOGAF）案例补强

**典型题干**：集团 200+ 业务系统林立、烟囱式建设、数据孤岛严重，要求整体规划。

**标准答案骨架**：

**(1) 现状梳理**：
- 系统清单与依赖关系
- 业务流程与组织
- 数据资产分布
- 技术栈与基础设施

**(2) 按四层架构设计目标蓝图**：

| 层次 | 内容 | 输出物 |
|------|------|--------|
| **业务架构** | 业务能力、流程、组织 | 业务能力图、流程图 |
| **应用架构** | 应用清单、协作、接口 | 应用矩阵、接口规范 |
| **数据架构** | 主数据、共享数据、治理 | 主题域、数据模型 |
| **技术架构** | 部署、网络、中间件、安全 | 技术栈、部署图 |

**(3) TOGAF ADM 迭代实施**：
预备 → A 架构愿景 → B 业务架构 → C 信息系统架构（应用+数据）→ D 技术架构 → E 机会与解决方案 → F 迁移规划 → G 实施治理 → H 架构变更管理

**(4) 治理机制**：架构评审委员会、技术选型标准、接口规范、主数据治理

**(5) 量化效果**：重复建设减少 30%、复用率 +55%、交付周期缩短 40%

### 13.6 微服务拆分粒度判断（题 2 常考）

**题干样式**：给出业务模块清单，要求拆分微服务并说明理由。

**拆分原则（DDD 方法）**：

1. **战略设计**：识别核心域、支撑域、通用域
2. **限界上下文 Bounded Context**：每个上下文对应 1-2 个微服务
3. **聚合根 Aggregate Root**：维护一致性边界
4. **服务粒度准则**：
   - **业务能力单一**：围绕单一业务能力
   - **数据私有**：每服务独立数据库
   - **团队规模**：2-pizza team（< 8 人）
   - **变更频率相近**：高频变更不与稳定模块绑定

**常见拆分维度**：
- 按业务域：用户、订单、商品、支付、库存
- 按读写分离：查询服务 vs 命令服务（CQRS）
- 按变化频率：稳定核心 vs 活动促销
- 按并发等级：高并发独立部署

**避免的反模式**：
- 过细："纳米服务"，运维负担过重
- 过粗：仍是单体只是换名字
- 共享数据库：违反微服务核心原则
- 同步链路过长：A→B→C→D→E（应改异步）

### 13.7 缓存一致性方案对比（题 2 高频）

| 方案 | 写策略 | 一致性 | 性能 | 风险 |
|------|--------|--------|------|------|
| **Cache Aside**（旁路） | 先更 DB，再删缓存 | 最终一致 | 高 | 极短不一致窗口 |
| **Read/Write Through** | 缓存代理写 DB | 强一致 | 中 | 缓存层成为瓶颈 |
| **Write Behind** | 异步写 DB | 弱 | 极高 | 宕机丢数据 |
| **双写** | 同时写 DB + Cache | 不可靠 | 中 | **不推荐**，易不一致 |

**一致性进阶方案**：
- **延迟双删**：写 DB → 删缓存 → 延迟 N 秒 → 再删一次
- **订阅 binlog**：通过 Canal 监听 MySQL binlog 自动更新缓存
- **分布式锁**：写操作加锁，串行化更新

### 13.8 分布式事务方案选型（题 2/题 3 常考）

| 方案 | 一致性 | 性能 | 复杂度 | 适用 |
|------|--------|------|--------|------|
| **2PC** | 强 | 低（阻塞） | 中 | 跨库事务、传统场景 |
| **3PC** | 强 | 较低 | 高 | 有超时要求 |
| **TCC** | 强 | 中 | **高**（业务侵入） | 资金、订单核心业务 |
| **Saga** | 最终 | 高 | 中 | 长事务（旅行预订） |
| **本地消息表** | 最终 | 高 | 低 | 通用异步 |
| **MQ 事务消息** | 最终 | 高 | 中 | RocketMQ 事务消息 |
| **Seata AT** | 强 | 中 | 低（无侵入） | 中后台一般场景 |

**选型决策树**：
```
是否资金/核心业务？→ 是 → TCC / Seata AT
        ↓ 否
能否最终一致？→ 是 → 本地消息表 / MQ 事务消息 / Saga
        ↓ 否
跨数据库？→ 是 → 2PC / Seata
```

### 13.9 题 4 类图补全套路（必考）

**典型题干**：给文字描述与缺失类图，要求补全类、关系、属性、方法。

**标准答题步骤**：

1. **找名词**：文字中的名词候选为**类或属性**
2. **找动词**：动词候选为**方法或关联**
3. **判断关系**：
   - "X 由 Y 组成" → 组合（同生死）/ 聚合（可分离）
   - "X 是一种 Y" → 泛化（继承）
   - "X 实现接口 Y" → 实现
   - "X 使用 Y" → 依赖/关联
4. **标多重性**：1、0..1、1..*、*
5. **画方法**：动词+宾语，对应业务操作

**常见易错点**：
- 关联方向写反
- 聚合 vs 组合混淆（**核心是生命周期**）
- 漏掉接口实现关系
- 多重性写在错误一端（注意：多重性写在**对端**）

### 13.10 题 1 效用树补全多场景示例

> 案例题 1 经常要求补效用树，下面提供 5 类常见质量属性的标注样例。

**电商系统效用树（H/M/L = 重要性, 难度）**：

```
效用 Utility
├── 性能 Performance
│   ├── 下单 P99 ≤ 1.5 秒 (H, M)
│   ├── 商品页 P99 ≤ 800ms (H, L)
│   └── 大促峰值 50000 TPS (H, H)
├── 可用性 Availability
│   ├── 全年可用 99.99% (H, M)
│   ├── 单服务故障 30 秒切换 (H, L)
│   └── 异地多活切换 5 分钟 (M, H)
├── 安全性 Security
│   ├── 支付链路 TLS 1.3 (H, L)
│   ├── 敏感数据 AES-256 加密 (H, L)
│   └── 风控误判率 < 0.01% (M, H)
├── 可修改性 Modifiability
│   ├── 新支付通道接入 ≤ 3 人天 (M, M)
│   └── 促销规则配置化 (H, M)
└── 可测试性 Testability
    └── 接口自动化覆盖率 ≥ 85% (M, M)
```

**填空套路**：
- 题目给场景片段 → 标注 (H/M/L, H/M/L)
- 重要性看业务影响、难度看技术挑战
- **高重要性 H** 是必保项，必须先实现

### 13.11 三种基础架构风格易混点辨析（题 1 常考）

| 风格 | 数据耦合 | 控制耦合 | 数据流向 | 典型应用 |
|------|---------|---------|---------|---------|
| **管道-过滤器** | 流式 | 弱（顺序触发） | 单向 | Unix管道、编译器、ETL |
| **黑板** | 共享内存 | 强（控制器协调） | 多向（读写共享） | AI、语音识别、IDE |
| **事件驱动** | 事件消息 | 弱（发布订阅） | 多向（异步） | GUI、消息系统 |

**经典考题判别**：
- 题目出现"过滤器""管道""数据流" → 管道-过滤器
- 题目出现"知识源""黑板""控制器" → 黑板
- 题目出现"事件""订阅""触发""通知" → 事件驱动

### 13.12 案例题常见易错点与失分点

| 易错点 | 正确做法 |
|--------|---------|
| 关键词不靠前 | 答案首句直接给结论，再展开 |
| 只写技术名词 | 写"机制 + 触发条件 + 预期效果" |
| 性能不量化 | 给具体指标（P99、TPS、RT） |
| 风险无应对 | 每个风险配 1 条应对措施 |
| 不分点 | ①②③ 或 1./2./3. 编号 |
| 答案与题干无关 | 50% 答案在题干，先标关键词 |
| UML 符号错 | 类图严格按标准：实/虚线、菱形空心/实心 |
| 时间分配失衡 | 题 1 不超 30 分钟，强制切换 |
